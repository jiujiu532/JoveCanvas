# JoveCanvas features overview

JoveCanvas puts creative planning, image and video generation, canvas, short-drama production, asset management, and commercial operations in one application. Users mainly express goals, audience, and constraints; the Agent forms a professional plan and selects real, available model capabilities.

## Five-stage creative loop

### 1. Creative brief

The Agent organizes goals, audience, use case, core message, content constraints, and reference strategy. When information is sufficient it fills gaps reasonably—users need not complete a large parameter form first.

### 2. Inspiration & visual direction

Internally the system forms recommended directions: style, composition or camera, color, lighting, visual keywords, and avoid-list. Planning data constrains later tasks and is **not** shown as long chat messages.

### 3. Full deliverable plan

Canvas Agent can plan dependencies among text, image, video, and audio while keeping context for companion assets. Chat shows only user input, necessary natural confirmations, concise completion hints, and real generation results.

### 4. Consistent generation

Real tasks inherit the same internal brief, visual direction, reference strategy, and upstream dependency summary. With smart planning on, the Agent chooses models and parameters; when the user picks a model and gives an explicit prompt, that choice is kept but still validated against Skills, capabilities, references, and billing. Model rationale and platform prompts are never shown or persisted into generation chat.

### 5. Automatic visual review

When a vision-capable text model is available, image results can run structured visual checks internally. Review detail is not written into generation chat, and a missing review model never blocks an already successful generation.

## Creative workbenches

### Image workbench

- Text-to-image, image-to-image, and reference editing.
- Multi-result generation, history restore, title rename, selective delete, failure retry.
- Smart planning auto-selects logical model, aspect ratio, quality, and count; off requires a user model choice.
- Manual model + precise prompt can run directly, still through Skill and capability checks.

### Video workbench

- Text-to-video, image-to-video, multi-type references.
- Real controls for aspect ratio, resolution, duration, audio, watermark.
- Async poll, refresh recovery, history, result delete.
- With reference images, emphasize first frame, subject, wardrobe, product, and composition consistency.

### Canvas

- Nodes for text, image, video, audio, creative brief, brand rules, and generation tasks.
- Drag, zoom, connect, minimap, box-select, multi-select, undo/redo, import/export.
- Canvas Agent reads the current board, plans multi-asset dependencies, and writes nodes/edges back.
- Tasks support dependency execution, pause, resume, cancel, failure retry, and refresh recovery.

### Short-drama pipeline

- Script analysis, characters & scenes, storyboard, shot video, voice, subtitles.
- FFmpeg full-episode assembly, Chinese subtitle burn-in, cancel, preview, download.
- Real video/audio channels and production images still need per-environment acceptance.

## Models & task execution

- Admins configure OpenAI-compatible channels, real models, and capability tags.
- Text/image/video/audio use stable logical model names; admin decides actual channels and priority.
- Channels support catalog pull, capability probes, timeouts, error redaction, and saved credentials.
- Generation tasks unify status, points, duration, entry, model, and result URLs.
- Plan / generate / review are billed server-side; refresh or SSE replay does not recreate tasks or double-charge; without explicit upstream failure the create API is not re-called automatically.

## Data & assets

- PostgreSQL stores users, creative sessions, workbench history, Canvas, assets, short drama, config, tasks, points, orders, and audit data.
- Image/video/audio are registered to server `VOZEB_PRO_DATA_DIR` or S3-compatible storage; business tables never store base64 or temporary signed URLs.
- Temporary references expire after 24h by default; long-lived uploads, results, and short-drama finals are deleted only by admins.
- Admin “local media”: classify, preview, expiry checks, single/batch delete, temp cleanup.
- Admin “external storage”: S3-compatible config, connection test, object management, batch migration of local media.

## Commerce & operations

- Users, roles, status, points, and plan entitlements.
- Daily free points, CDK, products, orders, payment channels, refunds, ledgers, reconciliation.
- Announcements, prompts, model channels, Agent Skills, local/external media, business backup, mail config.
- Model, payment, and SMTP secrets stay server-side.

## Platform, data & security

- **Database**: default PostgreSQL 16; accounts, sessions, config, creative sessions, messages, stable assets, Canvas, materials, drama, tasks, points, orders, payments, audit—all server-side. File provider is a legacy single-host fallback only.
- **Server pagination**: long chats load latest first with older pages; users/orders/points/prompts/CDK/generation/admin lists use server pagination or targeted queries.
- **Model routing**: real channels vs logical models; capability tags, defaults, priority, candidates, health probes, redacted errors, GlobalAiOpc isolation adapters.
- **Tasks & billing**: create idempotency, per-user/type concurrency, points pre-auth, terminal settle, failure refund, refresh recovery, user retry only after explicit failure; query timeouts do not recreate upstream tasks.
- **Media**: uploads/generation named by date-time + UUID; register original name, user, source, type, session/run/task/project links; pages use WebP preview; download returns originals.
- **Storage switch**: external off → new files local only; on → new files S3-compatible only, no new local durable copy; history reads by its own provider.
- **Media security**: ownership checks on user read; upstream refs use short-lived signed URLs; delete checks creative sessions, assets, Canvas, drama, generation refs.
- **Account security**: password hash, session cookie, email OTP failure limits, admin authz, API body size limits, trusted proxy hops, redacted errors, audit logs.
- **Personal rights**: users may export their business data and submit/withdraw deletion requests; formal delete and legal retention follow ops policy and human review.
- **Backup boundary**: admin business import/export excludes secrets and media binaries; production restore must cover PostgreSQL **and** local media or object storage.
- **Deploy**: source dev, standard Compose, source-build Compose, Baota PostgreSQL, external PostgreSQL, low-memory, Render; app and docs GHCR workflows for amd64/arm64.

## Current limits

- Video visual review only marks “unavailable” when a trusted cover/keyframe is missing—it never fakes a real visual check.
- Docker static paths, server media volumes, real payment refunds, and full Linux deploys still need the pending-test checklist.
- No scraping or copying unauthorized third-party galleries, fonts, icons, or brand assets.
